# CodeVision 설계 결정

2026-11-20 기준. 결정이 바뀌면 이 문서를 고쳐 가며 쓴다.

## 무엇을 만드나

바이브 코딩으로 만든 프로젝트의 폴더와 파일을 트리 도식으로 보여 주고, 파일마다 쉬운 한국어 설명을 붙여 주는 보조 도구.

## 형태

- 혼자 쓰는 로컬 앱으로 시작하되, 나중에 주변 사람들에게 배포할 수 있게 만든다.
- Python 백엔드 + 브라우저 화면(로컬 웹앱). 창 형태가 필요하면 pywebview를 쓴다.
- 입력은 두 가지다: GitHub 저장소, 로컬 폴더. 그 뒤의 분석 → 설명 → 트리 화면은 공통으로 쓴다.

## 분석과 설명

- 구조는 코드 분석으로 정확하게 잡고, 설명만 AI로 만든다.
  - Python: 표준 `ast` 모듈
  - JavaScript/TypeScript: tree-sitter
- 처음 지원 언어는 Python과 JavaScript/TypeScript.
- AI 설명 공급자는 **미정**이다(로컬 AI와 상용 LLM 중 고민 중, 2026-11-19). 지금은 공급자와 무관한 뼈대만 만든다: 설명 인터페이스, 공급자 선택 자리, 캐시, 프롬프트 초안. 공급자를 정하기 전까지 화면은 규칙 기반 요약을 보여 준다.
- 설명은 파일 내용 해시(git과 같은 blob SHA-1) 기준으로 캐시한다. 내용이 바뀌지 않은 파일은 다시 요청하지 않는다.
- 웹 서버는 Python 표준 라이브러리(`http.server`)만 쓴다. 의존성이 적어 실행 파일로 묶기 쉽다.
- 로컬 서버 보안: 127.0.0.1에만 열고, 실행할 때마다 만드는 토큰과 Host 검사로 다른 웹사이트가 내 폴더 분석 결과를 읽지 못하게 한다.

## GitHub 연동

- GitHub App + 기기 코드 로그인(device flow). 앱이 보여 주는 코드를 github.com/login/device에 입력하는 방식으로, `gh` CLI와 같다.
- 권한은 읽기 전용(Contents, Metadata)이고, 사용자가 고른 저장소만 읽는다.
- 앱 안에 client secret을 넣지 않는다. Client ID는 공개값이라 코드에 들어가도 된다.
- 지금은 "이 계정에만 설치 가능"으로 등록하고, 배포할 때 공개로 바꾼다. 코드는 고치지 않는다.
- 저장소는 tarball API(호출 1번)나 `git clone --depth 1`로 한 번에 받는다. 파일마다 API를 호출하지 않는다(요청 한도 때문).
- LFS 파일, 바이너리, 너무 큰 저장소는 건너뛴다.
- 나중 기능 후보: AI가 방금 바꾼 파일 강조(커밋 기준), 브랜치 비교.

## 비밀 정보와 데이터

- GitHub 토큰과 (상용 LLM을 고르면) AI API 키는 OS 자격 증명 저장소에 둔다(Python `keyring` → Windows 자격 증명 관리자, macOS 키체인). 코드, 설정 파일, 깃에는 남기지 않는다.
- AI 키는 사용자마다 각자 입력한다. 배포판에 개발자 키를 넣지 않는다.
- 분석 결과와 설명 캐시는 각 사용자 PC에만 저장한다. 서버는 운영하지 않는다.

## 배포

- PyInstaller로 실행 파일 하나로 묶는다. 받는 사람은 Python을 설치하지 않아도 된다.
- 맥용은 맥에서 따로 빌드한다.

## 화면 디자인

- 참고 이미지 방식: 위에서 아래로 내려가는 트리, 속이 찬 원 안에 아이콘, 이름은 원 오른쪽, 직각으로 꺾이는 연결선.
- 색: 화면 코드 보라(#534AB7), 서버 코드 초록(#0F6E56), 문서·설정 회색(#5F5E5A), 정리 후보 주황(#BA7517).
- 파일을 누르면 패널에 설명, 주요 함수, "이 파일이 쓰는 파일"과 "이 파일을 쓰는 파일"이 나온다. 패널은 1024px 이상에서는 그림 옆에 붙어 있고(스크롤해도 보임), 그보다 좁으면 그림 아래에 있다. (2026-11-19 변경: 시안에서는 항상 아래였지만, 실제 프로젝트에서는 그림이 길어서 패널이 화면 밖으로 밀려났다.)
- 주요 함수는 항목마다 이름 바로 아래에 설명을 조금 들여 쓴다. (2026-11-20 변경: 시안은 설명을 이름 옆에 이어 썼는데, 이름이 길면 설명이 다음 줄로 밀려 다음 함수와 같은 간격이 되었고, 어느 설명이 어느 함수의 것인지 알기 어려웠다.)
- 폴더는 깊이마다 한 갈래만 펼친다(아코디언). 같은 깊이의 다른 폴더를 열면 열려 있던 쪽이 접힌다. 파일이 많은 프로젝트에서도 한 화면에 담기는 크기를 유지하기 위해서다.
- 접힌 폴더에는 "n개 항목"을, 그 안에 선택한 파일과 이어진 파일이 있으면 "연결 n개"를 표시한다.
- 형제가 많아 한 줄에 다 들어가지 않으면 최대 4줄로 나눠 그린다(파일 먼저, 폴더는 마지막 줄). 그래도 안 되면 그 묶음부터 아래만 같은 원과 연결선을 쓰는 들여쓰기 목록으로 그리고, 위쪽은 트리로 유지한다. 휴대폰처럼 좁은 화면은 전체가 들여쓰기 목록이다. (2026-11-19 변경: 시안은 전부 트리 아니면 전부 목록이었는데, 그러면 이 저장소처럼 루트에 항목이 10개인 프로젝트가 넓은 화면에서도 목록으로만 보였다.)
- 아이콘은 앱 안에 들어 있다(`web/icons.css`, Tabler 모양, MIT). 인터넷이 끊겨도 아이콘이 보이고, 앱이 다른 사이트에 아무것도 요청하지 않는다.
- 화면 맨 위에 연결된 저장소를 "GitHub · 저장소 · 브랜치"로 표시한다.
- 디자인 원본: `design/mockup.html`(브라우저로 열기, Windows 테마에 따라 라이트·다크 전환), 화면 캡처는 `design/screenshots/`, 참고 이미지는 `design/reference.png`. 위의 세 변경(옆 패널, 줄바꿈·혼합 배치, 주요 함수 배치)과 글자의 작은 차이(개수의 천 단위 쉼표, 한 덩어리로 이어지는 출처 줄 등)는 원본에 없고 실제 앱에만 있다. 자세한 배치 규칙과 차이 목록은 `docs/architecture.md` 7-1.
