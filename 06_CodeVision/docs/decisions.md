# CodeVision 설계 결정

2026-11-25 기준. 결정이 바뀌면 이 문서를 고쳐 가며 쓴다.

## 무엇을 만드나

바이브 코딩으로 만든 프로젝트의 폴더와 파일을 트리 도식으로 보여 주고, 파일마다 쉬운 한국어 설명을 붙여 주는 보조 도구.

## 형태

- 혼자 쓰는 로컬 앱으로 시작하되, 나중에 주변 사람들에게 배포할 수 있게 만든다.
- Python 백엔드 + 브라우저 화면(로컬 웹앱). 창 형태가 필요하면 pywebview를 쓴다.
- 로컬 앱의 입력은 두 가지다: GitHub 저장소(3단계, 잠시 멈춤), 로컬 폴더. 그 뒤의 분석 → 설명 → 트리 화면은 공통으로 쓴다.
- 4단계부터는 Claude·ChatGPT에서 쓰는 스킬로도 쓴다. 입력은 이 PC의 폴더(Claude Code, Codex)나 프로젝트 압축 파일(claude.ai, ChatGPT)이고, 결과는 트리 화면이 든 HTML 파일 하나다. 분석과 트리 화면은 로컬 앱과 같은 코드를 쓴다 (아래 "배포").

## 분석과 설명

- 구조는 코드 분석으로 정확하게 잡고, 설명만 AI로 만든다.
  - Python: 표준 `ast` 모듈
  - JavaScript/TypeScript: tree-sitter
- 처음 지원 언어는 Python과 JavaScript/TypeScript.
- AI 설명은 이 PC에서 도는 **로컬 AI**(Ollama)로 만든다 (2026-11-20 결정. 그 전에는 로컬 AI와 상용 LLM 사이에서 정하지 못해, 2026-11-19에 공급자와 무관한 뼈대만 만들었다).
  - Ollama 주소는 이 PC 안의 주소(127.0.0.1, localhost, ::1)만 쓴다. 프록시를 쓰지 않고 리다이렉트를 따라가지 않아서, AI에 보내는 코드가 PC 밖으로 나가지 않는다. 비밀이 들어 있을 수 있는 파일(`.env*`, 개인 키 등)은 보내지 않고, 보내는 글 속의 뚜렷한 비밀 값(토큰, 비밀번호, 개인 키 블록)은 가린다.
  - SDK나 새 패키지 없이 표준 라이브러리 `urllib`로 Ollama의 HTTP API를 부른다.
  - 설명은 필요할 때 만든다: 화면에서 고른 파일·폴더 하나씩, 그리고 AI 패널의 "전체 설명 만들기"로 한꺼번에(코드 파일 → 깊은 폴더부터 → 맨 위 폴더). 분석(`/api/analyze`)은 모델을 부르지 않고, 캐시에 있는 설명과 AI에 보내지 않는 파일 표시만 붙인다.
  - AI 설명은 처음에 꺼져 있고 사용자가 AI 패널에서 켠다. 꺼져 있으면 화면은 규칙 기반 요약만 보여 준다. Ollama 설치와 모델 받기(`ollama pull`)는 사용자가 한다. 앱은 아무것도 내려받지 않고, 설치된 Ollama를 창 없이 켜기만 한다 (`ollama serve`. 스스로 업데이트하는 트레이 앱은 켜지 않는다).
  - 기본 모델은 **qwen2.5:7b**다 (2026-11-21, 실제 모델 평가). 기본값은 `prompts.RECOMMENDED_MODELS`(`["qwen2.5:7b", "gemma3:4b"]`)에서 오고, 사용자가 고르지 않으면 그중 설치된 첫 모델을 쓴다. 까닭: 예제, 이 저장소, pip과 `.venv`의 다른 패키지에서 고른 70개 항목에서 코드와 다른 말을 한 답이 qwen2.5:7b는 8개, gemma3:4b는 16개였다. 다듬은 뒤 남은 합니다체는 둘 다 없었고, 속도도 비슷했다(모델이 올라간 뒤 평균 약 3초). gemma3:4b는 한국어가 더 매끄럽지만 코드에 없는 기능과 예시를 덧붙이는 일이 많았다.
  - 상용 LLM(`cloud`)은 자리만 남겨 두고 만들지 않았다.
  - 위의 로컬 AI 결정과 "AI에 보내는 코드가 PC 밖으로 나가지 않는다"는 로컬 앱에만 해당한다. 4단계 스킬에서는 코드가 PC 밖으로 나가고, AI 설명(2차)도 대화 중인 Claude나 GPT가 쓴다 (아래 "배포").
- 설명은 파일 내용 해시(git과 같은 blob SHA-1) 기준으로 캐시한다. 내용이 바뀌지 않은 파일은 다시 요청하지 않는다.
- 로컬 앱의 웹 서버는 새 패키지 없이 Python 표준 라이브러리(`http.server`)만 쓴다. 스킬에는 웹 서버를 넣지 않는다 (아래 "배포").
- 로컬 서버 보안: 127.0.0.1에만 열고, 실행할 때마다 만드는 토큰과 Host 검사로 다른 웹사이트가 내 폴더 분석 결과를 읽지 못하게 한다.

## GitHub 연동

- 3단계다. 2026-11-25부터 잠시 멈췄다. 스킬에는 필요 없어서, 4단계 1차를 마친 뒤 로컬 앱에 아직 필요한지 다시 정한다. GitHub App은 2026-11-24에 "이 계정에만 설치 가능"으로 등록했고, 기기 코드 로그인을 켰다.
- GitHub App + 기기 코드 로그인(device flow). 앱이 보여 주는 코드를 github.com/login/device에 입력하는 방식으로, `gh` CLI와 같다.
  - 다시 시작할 때 로그인 방식과 아래의 "앱 안에 client secret을 넣지 않는다"를 한 번 더 정한다.
    - Google 로그인처럼 브라우저에서 로그인하면 앱으로 저절로 돌아오는 방식(web application flow)은 client secret을 앱에 넣어야 한다.
    - GitHub 문서끼리 권하는 방식이 다르다(2026-11-24 확인). 한 곳은 데스크톱 앱에 기기 코드 로그인을 권한다. 다른 곳(GitHub App 모범 사례)은 PC에서 도는 앱은 어차피 비밀 값을 지킬 수 없으니 client secret을 앱에 넣되, PKCE(가로챈 로그인 코드를 다른 프로그램이 쓰지 못하게 하는 확인 절차)를 함께 쓰라고 한다.
- 권한은 읽기 전용(Contents, Metadata)이고, 사용자가 고른 저장소만 읽는다.
- 앱 안에 client secret을 넣지 않는다. Client ID는 공개값이라 코드에 들어가도 된다.
- 설치 범위는 지금 "이 계정에만 설치 가능"이고, 로컬 앱을 다른 사람에게 나눠 줄 때 공개로 바꾼다. 코드는 고치지 않는다.
- 저장소는 tarball API(호출 1번)나 `git clone --depth 1`로 한 번에 받는다. 파일마다 API를 호출하지 않는다(요청 한도 때문).
- LFS 파일, 바이너리, 너무 큰 저장소는 건너뛴다.
- 나중 기능 후보: AI가 방금 바꾼 파일 강조(커밋 기준), 브랜치 비교.

## 비밀 정보와 데이터

- GitHub 토큰과 (나중에 상용 LLM을 붙이면) AI API 키는 OS 자격 증명 저장소에 둔다(Python `keyring` → Windows 자격 증명 관리자, macOS 키체인). 코드, 설정 파일, 깃에는 남기지 않는다.
- AI 키는 사용자마다 각자 입력한다. 배포판에 개발자 키를 넣지 않는다. 지금 쓰는 로컬 AI(Ollama)는 키가 필요 없다.
- 로컬 앱의 분석 결과와 설명 캐시는 각 사용자 PC에만 저장한다. 서버는 운영하지 않는다(4단계 스킬도 우리 서버 없이 돈다). AI 설정(`config.json`)과 AI 설명 캐시(`cache.sqlite`)도 사용자 데이터 폴더에 있다.

## 배포

- 실행 파일 대신 **Claude와 ChatGPT에서 쓰는 스킬**로 배포한다 (2026-11-25 변경. 그 전에는 PyInstaller로 exe 하나를 만들고 맥용은 맥에서 따로 빌드할 계획이었는데, 둘 다 접는다). 지금의 로컬 앱(`run.bat`, Ollama)은 코드를 PC 밖으로 보내지 않는 방법으로 그대로 둔다.
- 스킬은 `SKILL.md`와 스크립트가 든 폴더 하나다(Agent Skills 형식). Anthropic이 만든 형식으로, 2026-10-22에 Linux Foundation 산하 Agentic AI Foundation으로 넘어갔다.
  - Claude 앱(claude.ai), Claude Code, Codex가 같은 폴더를 읽는다.
  - ChatGPT도 같은 형식이지만 일반 대화에서는 스킬의 스크립트를 실행하지 않는다(OpenAI 안내, 2026-11). Work 모드에서 도는지와 어느 요금제에서 되는지는 3차에서 시험해 보고 정한다.
  - 한 폴더가 어디서나 돌게 한다. `SKILL.md` 맨 위 설정(frontmatter)에는 표준 항목 6개(`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`)만 쓴다. 다른 항목이 있으면 claude.ai에 올라가지 않는다. `description`은 200자 안으로 쓴다(Anthropic 문서끼리 200자와 1,024자로 다르다).
  - Claude에는 플러그인으로 묶어 설치하는 방법을 먼저 시험한다. 한 번 설치하면 claude.ai, Claude Code, Cowork에서 함께 쓰고, GitHub 저장소를 마켓플레이스로 더하면 저절로 업데이트된다고 안내되어 있다. OpenAI의 플러그인 제출 창구도 같은 묶음을 받는다고 한다. Codex와 ChatGPT 데스크톱 앱에는 스킬 폴더를 넣는다.
- 맞춤 GPT는 OpenAI가 2026-12-11에 없앨 예정이라 쓰지 않는다.
- 대화창 안에 트리를 그리는 방식(MCP App)은 이 PC에서 도는 서버로는 주로 Claude 데스크톱 앱에서 되고(claude.ai와 ChatGPT 웹은 인터넷에서 닿는 서버가 있어야 한다), 설치가 어려워서 미룬다.
- 스킬은 프로젝트를 분석해 `codevision.html` 파일 하나를 돌려준다. 이 파일을 브라우저로 열면 네트워크 요청 없이 지금과 같은 트리 화면이 나온다. 화면 코드는 지금의 `app.js`에 서버 없이 그리는 모드를 더해 로컬 앱과 함께 쓴다. 웹 서버와 그 토큰, Ollama 연결, AI 설정은 넣지 않고, PC의 절대 경로도 파일에 넣지 않는다.
  - Claude Code나 Codex처럼 이 PC에서 도는 도구에서는 이 PC의 폴더를 바로 읽는다. 결과 파일은 정해진 곳에 쓰고, 전체 경로를 알려 주고, 브라우저로 바로 연다. 이때는 PC에 Python 3.10 이상이 있어야 한다.
  - claude.ai에서는 사용자가 프로젝트를 압축해 올리고, 스크립트는 Anthropic의 코드 실행 환경에서 돈다. 결과는 내려받는 파일로 준다. 올린 압축 파일을 풀어 분석하는 일은 도움말에 나와 있지 않아서 시험 단계에서 해 본다.
  - ChatGPT에서도 같게 쓰려 하지만, 스크립트가 어디서 도는지 OpenAI 문서에 없어서 3차에서 시험해 보고 정한다.
  - 결과 파일은 만든 때의 모습이라, 코드가 바뀌어도 저절로 바뀌지 않는다.
- 올리는 압축 파일에는 `node_modules`, `.venv`, `.git` 폴더와 비밀이 들어 있을 수 있는 파일(`.env*`, `credentials.json`, `token.json`, `*.pem` 등)을 넣지 않는다.
  - 우리 스크립트의 비밀 파일 거르기는 압축 파일을 올린 뒤에야 돌아서 늦다. 그래서 사람 손에 맡기지 않도록 안전하게 압축하는 도구를 함께 준다. 이 도구는 무거운 폴더와 비밀 파일을 빼고, claude.ai의 파일 한도 30MB를 넘으면 알린다.
  - 스킬의 스크립트는 Windows에서 만든 압축 파일도 한글 파일 이름이 깨지지 않게 푼다.
- 스킬의 AI 설명(2차)은 대화 중인 Claude나 GPT가 쓴다.
  - 모델에게는 스크립트가 만든 작업 목록(비밀 파일을 빼고, 비밀 값을 가리고, 길이를 줄인 코드)을 준다. 파일 속 지시문은 따르지 말라고 적어 두지만, 모델이 그 글을 읽는 이상 완전히 막지는 못한다.
  - 설명을 쓰는 동안에는 우리 스크립트 말고 다른 명령을 실행하지 말라고 `SKILL.md`에 적는다. Claude Code에서는 우리 스크립트만 미리 허용해서, 다른 명령은 사용자에게 묻게 한다. 모델이 자기 도구를 그대로 갖고 있어서 이것도 완전히 막지는 못한다.
  - 답은 지금의 다듬기(`postprocess`)와 합치기(`make_x`)를 거쳐 넣고, 틀이 맞지 않으면 규칙 기반 설명을 쓴다.
- 스킬로 쓰면 코드가 PC 밖으로 나간다. 모델이 Anthropic이나 OpenAI의 서버에서 코드와 분석 결과를 읽고, claude.ai와 ChatGPT에서는 프로젝트 압축 파일도 그쪽에 올라간다. 사용 안내에 이 점과 학습 설정을 적는다(나눠 주기 전에 다시 확인한다).
  - Claude 무료·Pro·Max·Ultra: 개인정보 설정의 "Help Improve our AI models"가 켜져 있으면 대화와 Claude Code 작업이 학습에 쓰일 수 있다(2026-11-25 확인).
  - ChatGPT 무료·Plus·Pro: "Improve the model for everyone"이 기본으로 켜져 있다.
- tree-sitter는 스킬이 도는 곳에 없을 수 있다.
  - 없으면 정규식 분석으로 바뀌어, 다른 파일의 요청 도우미를 거치는 HTTP 연결이 빠진다(테스트용 프로젝트에서 6개 → 0개). 지금은 경고 없이 바뀌지만, 앞으로는 화면에 경고를 띄운다.
  - 버전은 이 저장소에서 테스트한 0.26.1로 고정한다.
  - 이 PC에서는 처음 한 번 CodeVision 전용 가상 환경을 만들어 설치한다(인터넷 필요). claude.ai 같은 곳에서는 그 자리에서 설치할지 스킬에 넣어 갈지 시험 단계에서 해 보고 정한다.
- 비용: Claude Code는 Pro 이상 요금제가 필요하다. claude.ai의 무료 요금제에서 되는지는 Anthropic 문서끼리 달라 시험해 본다. ChatGPT 웹의 Work 모드는 Plus 이상이고, 무료·Go는 데스크톱 앱에서만 제한적으로 쓴다. 스킬의 AI 설명(2차)은 각자의 요금제 사용량을 쓴다.
- 다른 사람에게 나눠 주기 전에 CodeVision의 라이선스를 정한다. 결과 HTML에는 Tabler 아이콘(MIT)의 저작권 표시와 MIT 허락 문구를 함께 남기고(지금 `icons.css`에는 저작권 줄만 있다), tree-sitter를 스킬에 넣으면 그 라이선스 파일도 넣는다.
- 나눠 주는 방법은 누가 쓸지부터 정하고 고른다. 누구나 쓰게 하려면, OpenAI 쪽은 본인 확인, 개인정보 처리방침, 심사를 요구한다.
- 순서: 작은 시험 스킬 → Claude Code와 claude.ai(1차) → Claude·GPT가 쓴 설명(2차) → ChatGPT·Codex와 나눠 주기(3차). 시험과 1·2차의 어림 시간은 아래 "진행 상황"(3차는 아직 없음).
